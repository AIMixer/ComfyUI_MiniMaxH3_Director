# r2v 参考音频原声输出 — 问题与修复说明

本分支(`r2v-source`)相对上游 main 的音频相关改动与原理记录。

## 一、修复前的问题

1. **r2v 的 `audioMode=source`(使用原声)完全失效** — 后端被静默回退为 `generate`,且前端 UI 直接隐藏了"声音"下拉,r2v 任务里根本选不了。
2. 结果:输出音频永远是 **H3 模型生成的声音** — 参考音频明明挂了,成片声音却**不像参考音频的音色**(音色是模型"模仿"出来的,近似而非复制)。
3. 多段任务(全部导出):只有第一个素材组有声,后续段静音。

## 二、根因

| 层 | 问题 |
|---|---|
| 后端 | `audio_export.py` 的 `VIDEO_EDIT_AUDIO_TASKS = {"v2v","rv2v"}` — source 模式只认 v2v/rv2v;`resolve_audio_mode()` 对 r2v 无条件强制回退 `generate` |
| 前端 | `minimax_timeline.js` 仅对 v2v/rv2v 显示"声音"下拉,r2v 下隐藏 |
| 多段 | 全部导出时只取"第一个有音频的段"填充整条时间轴,后续段无音频 |
| 格式 | 参考音频 wav 的采样率/声道不统一时,mux 后被按错误采样率播放(16kHz 当 44.1kHz → 加速 2.75 倍、"叽叽喳喳 3~4 秒") |

## 三、修复内容(本分支提交)

| 提交 | 内容 |
|---|---|
| `f6da62c` | ① r2v 加入 source 白名单;② source 时无源视频 → 回退用段/全局**参考音频** mux;③ 前端 r2v 显示"声音"下拉 + tooltip 更新 |
| `eaab39c` | **自动归一化**:mux 前任何格式的参考音频自动重采样到 44.1kHz 立体声(时长不变) |
| `fade6f3` | **多段拼接**:全部导出时每段用各自参考音频按时间轴拼接(段级优先,未挂回退全局,都无则该段静音) |

## 四、为什么修复后"声音像了"

关键区别在**输出音频的来源**:

| 模式 | 输出音频 | 音色 |
|---|---|---|
| 修复前(r2v 被强制 generate) | **模型生成**(AV latent 解码) | 参考音频只是"条件",模型模仿音色 — 近似,不像 |
| 修复后(source 生效) | **参考音频 wav 原样 mux** | 零生成、零音色损失 — 就是它本身 |

补充:参考音频**作为条件**喂给模型的链路(修复前后都是通的):

```
ref_audios → MiniMaxH3ReferenceToVideo._encode_ref_audio
           → AudioVAE(32kHz)→ AV latent → 驱动画面口型/节律
```

即:修复是把"输出"从模型生成切换为 wav 原样,同时保留条件通道让画面贴合原声 — **双通道**。

## 五、使用约定

- **`audioMode=source`(用原声)**:输出 = 参考音频;prompt 里 audio 标签写 `fully_copy`(画面贴合原声);**台词内容必须与音频一致**,否则口型/内容错位
- **`audioMode=generate`(生成声音)**:输出 = 模型生成(可改词);prompt 写 `reference` — 此路径行为与官方完全一致,本分支未改动
- 参考音频格式随意(自动归一化);每段挂各自的(段级覆盖全局),或全局挂一套共用
- 想要 BGM:generate 输出不含 BGM(H3 音频生成为对白主导),BGM 后期混;source 则原样保留

## 六、相关注意事项(缓存/批量)

- **seed 固定(fixed)** 才能让未改动段命中缓存;`randomize` 每次运行换种子 → 勾选段永远重采样
- **勾选 = 强制重新采样**(与缓存无关,普通运行不查一采缓存);**不勾 = 读缓存合并**
- 全部导出的未勾选段必须有历史缓存,否则成片缺段
- 合并内存 ≈ 总帧数 × 4.98MB(0.4MP 竖屏):11 段 ≈ 13GB、20 段 ≈ 24GB — 64GB 内存机器 15 段为舒适上限,更多段建议分段导出 + ffmpeg 拼接,或等待上游"延迟拼接"方案(PR63)
- 若 Director 节点被删除重建,node_id 变化 → 段缓存目录(`minimax_seg_cache/<node_id>/`)分家,旧缓存需手动迁移
