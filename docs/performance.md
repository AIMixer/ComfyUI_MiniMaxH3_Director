# 性能与验收记录（2026-11-02）

环境：RTX 5070 12GB、32GB RAM，ComfyUI 0.43.0、PyTorch 2.13.0+cu130、前端 1.57.6。使用本机 INT8 hybrid b25-49 底模、INT4 Qwen3-VL 编码器、INT8 视频 VAE、FP32 音频 VAE和相同 FL2VA 适配器。

所有下列对照均为 **832×480、124 帧、24fps、seed42**，逐字相同的纯文提示词，相同模型文件与适配器、CFG1、lcm 和精确六步噪声表。关闭续接、二采、修脸、实时预览和额外下游视频保存。视频解码均为原生 tiled 512/64、时间块64/8。只复用加载器时，条件编码、采样和双路解码仍实际执行。

## 当前本机维护版与 Pro

按收敛后的执行要求，每侧只运行一次，新进程冷启动、不额外预热。两边均使用 H3 自定义采样入口、外接原生 LoRA Loader 和 ManualSigmas；这是相同配方的路径对照，不是对完整25步 H3 默认配方的测速。

| 实现 | 完整耗时 | 条件编码 | 采样 | 双路解码 |
| --- | ---: | ---: | ---: | ---: |
| 本机实际安装维护版 | 225.105秒 | 24.1秒 | 151.2秒 | 23.5秒 |
| Pro | 140.959秒 | 11.9秒 | 87.0秒 | 37.3秒 |

本次完整耗时减少约 **37.4%**。顺序为 Pro 先、原安装后；未人为清空操作系统、磁盘或驱动缓存。仅一次对照，不推导所有硬件和任务都有相同收益。两个进程均未命中执行缓存，原安装及其未发布扩展没有被改写。

## Pika 与原生工作流

复用执行节奏收敛前已经完成的三对热态记录，不为重新排顺序而补跑。

| 工作流 | 完整耗时中位数 | 实际范围 |
| --- | ---: | ---: |
| 本机 ComfyUI 原生节点 | 123.449秒 | 119.930–129.911秒 |
| Pro 的 Pika-H3 模式 | 125.037秒 | 120.454–136.882秒 |

中位数相差 **1.588秒（约1.29%）**，Pro 中位数落在本次原生重复运行范围内；存在波动，不能保证每次更快。采样阶段中位数约82.4／90.2秒，双路解码约16.5／15.7秒。历史101.29秒不作为当前环境的直接基准。

两边输出均为 H.264/yuv420p、CRF18，但编码器实现不同：原生使用 PyAV 默认预设与 AAC 码率；导演台内部使用 FFmpeg veryfast、AAC192k及PCM16中间音频。不能声称封装编码参数或文件字节完全一致，也不以文件大小判断生成质量。

## 已验证与限制

- 真实生成对照的正式 MP4 均核查124帧、832×480、24fps、32kHz双声道音轨及完整解码；检查有限数值和非静音，不代替主观画质、运动或口型评估。
- CPU整合验证包括短音轨补尾、静音、硬切内存/磁盘一致、映射文件释放、成品视频/纯拼接零采样和一采等待确认；部分模型/I/O边界使用stub。
- 真实浏览器验证模式过滤、固定配方显示、旧工作流参数迁移、按名称保存重开、旧Pika开关、H3参数保留及自动/中/英切换。
- 未扩展全模式反复测速、AMD/XPU硬件验证、大型长片峰值或全部Issue的原环境复现；未完成项在[逐项记录](upstream-review.md)明确区分。

最主要的修正是补齐内部原生节点的资源阶段边界：预取队列清理、转换缓冲释放与动态显存水位重置，顺序与本机 `execution.py` 一致；同时去掉单条结束后的强制全模型卸载。它会实际同步与释放工作集，不只是改计数，也不更改采样步数、画布、种子或画质配方。

API输入、模型/素材哈希、history、事件、资源快照与媒体检查保留在本机维护记录；私人提示词、素材和绝对路径不随本仓库发布。
